# MxCam vs 다른 녹화 방식 벤치마크 (2026-11-01)

PC: RTX 3070 Ti / Windows 11 / 1920×1080. 녹화 영역 1280×720, 30fps.
장면 ① 움직이는 테스트 영상(testsrc2) 20초 → CPU·메모리·용량·실제 프레임수
장면 ② 정지 고해상도 화면 8초 → 화면에 표시된 원본(무손실 캡처) 대비 화질 SSIM

| 녹화기 (설정) | CPU(전체 코어 대비) | 메모리 | 움직임 MB/분 | 실제 FPS | 정지화면 MB/분 | 화질 SSIM |
|---|---|---|---|---|---|---|
| **MxCam** (자동 → NVENC HEVC, 3단계, +AAC) | 3.0% | 339 MB | **21.4** | **30.0** | 3.95 | 0.986 |
| oCam 5.5 (기본값, H.264 +AAC) | 2.5% | 721 MB (광고 WebView2 569 MB 포함) | 51.4 | 24.1 | 6.42 | 0.990 |
| ffmpeg gdigrab + x264 veryfast (CPU, 소리 없음) | 4.7% | 270 MB | 18.6 | 29.7 | 1.42 | 0.985 |
| ffmpeg ddagrab + NVENC H.264 (GPU, OBS·ShadowPlay 방식, 소리 없음) | 0.2% | 112 MB | 25.3 | 29.9 | 1.80 | 0.990 |

## 해석
- MxCam은 oCam 대비 움직이는 화면 용량 **약 58% 작고**, 프레임 누락 없이 30fps 유지 (oCam은 24fps로 떨어짐).
- 메모리는 oCam의 절반 이하 (oCam은 광고용 WebView2가 569 MB 차지).
- 정지 화면 화질은 oCam/ddagrab보다 약간 낮음(0.986 vs 0.990) — 품질 4단계로 올리면 해소.
- 정지 화면 용량은 소리(AAC 160 kbps ≈ 1.2 MB/분) 포함 수치. ffmpeg 두 방식은 소리 없음.
- GPU 캡처(ddagrab)는 CPU·메모리가 가장 적음 → MxCam의 다음 개선 후보 (현재는 oCam과 같은 GDI 캡처).

## 측정 주의
- oCam은 녹화 영역 설정값에 테두리가 포함되어 1264×708로 녹화됨 → 화질은 위치를 맞춰(dx=5, dy=5) 비교.
- oCam의 게임 녹화 후킹(HookSurface)이 Direct3D로 그리는 창을 멈추게 해서, 테스트 영상은 소프트웨어 렌더링으로 재생.
- 화면 내용이 달라지면 수치도 달라짐. 한 번의 측정 결과임.
